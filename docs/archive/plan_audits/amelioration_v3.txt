 Section 0 — Gestion des dimensions (référence unique)

 Formule baseline

  d_clause    = 79   (UPOS 18 + dep_rel 38 + subj_pos 5 + tense 5 + aspect 4 + mood 5 + polarity 1 + flags 3)
 d_emb       = 0 ou N
 d_effective = d_clause + d_emb                         (sans B)
             = d_clause + d_emb + 2*d_emb               (avec B : +2*d_emb)
             = d_clause + 3*d_emb                        (avec B, simplifié)
  d_conn      = 31   (sans connector_lemmas définis)
 d_edge_CL   = 2*d_effective + d_conn + 4 + 2*d_emb + 2*d_effective + 2*n_node_types

 Point unique de vérité

 FeatureVocabulary.d_clause_effective(d_emb, subject_object_emb) dans layer1/features.py :
 def d_clause_effective(self, d_emb: int, subject_object_emb: bool = False) -> int:
     return self.d_clause + d_emb + (2 * d_emb if subject_object_emb else 0)
 train.py doit appeler cette méthode — jamais recalculer manuellement.

 Contrainte multi-tête (CORRECTION défaut #1)

  d_effective % n_heads doit être nul. Valeurs compatibles mesurées (d_clause=79) :
  d_emb=48 → d_eff=127 → nombre premier — INCOMPATIBLE avec n_heads > 1  ← ERREUR v3 corrigée
  d_emb=49 → d_eff=128 → compatible avec n_heads ∈ {1, 2, 4, 8}  ← valeur recommandée
  d_emb=53 → d_eff=132 → compatible avec n_heads ∈ {1, 2, 4} seulement

  Règle : si n_heads > 1, utiliser d_emb=49 (d_eff=128). Valider dans le CLI avec message d'erreur
  explicite suggérant des valeurs compatibles.

 Amélioration A — Pooling des tokens de contenu

 Problème corrigé

 Mean-pool sur TOUS les tokens inclut mots grammaticaux (DET, ADP, PUNCT) qui diluent la sémantique. Solution : filtrer par UPOS de contenu avant pooling.

 Implémentation

 layer1/features.py — vectorize_clause() :

 CONTENT_POS = {'NOUN', 'VERB', 'ADJ', 'PROPN', 'ADV'}

 def _pool_tokens(rep, word_embedding, mode):
     """Pool embeddings des tokens de contenu (NOUN/VERB/ADJ/PROPN/ADV)."""
     content = [t for t in rep.tokens if t['pos'] in CONTENT_POS]
     targets = content if content else rep.tokens   # fallback si aucun contenu
     vecs = [word_embedding.lookup(t['lemma']) for t in targets]
     if mode == 'mean':
         return np.mean(vecs, axis=0).astype(np.float32)
     else:  # 'max'
         return np.max(vecs, axis=0).astype(np.float32)

 Paramètre clause_pooling: str = "root" ajouté à vectorize_clause(), vectorize_edge().
 "root" = comportement actuel (rétrocompatible).

 Amélioration D — Attention multi-tête dans RGCNLayerGAT

 Contrainte de divisibilité (CORRECTION défaut #1)

 Dans RGCNLayerGAT.__init__() :
 if d_out % n_heads != 0:
     # Calculer les valeurs compatibles les plus proches
     compatibles = [n for n in [1,2,4,8] if d_out % n == 0]
     raise ValueError(
         f"d_out={d_out} non divisible par n_heads={n_heads}. "
         f"n_heads compatibles : {compatibles}. "
          f"Avec d_emb=49 : d_out=128 compatible avec n_heads ∈ {{1,2,4,8}}."
     )
 self.d_head = d_out // n_heads

 Implémentation de _gat_forward() multi-tête

 W_r reste (n_relations, d_out, d_in) inchangé. Chaque tête h accède à la tranche [h*d_head:(h+1)*d_head] de la sortie :

 out_heads = []
 for h_idx in range(self.n_heads):
     s, e = h_idx * self.d_head, (h_idx + 1) * self.d_head
     out_h = H @ self.W_0[s:e].t()   # self-loop tête h

     if edge_index.shape[1] > 0:
         for r in range(self.n_relations):
             mask = rtypes == r
             if not mask.any(): continue
             src_r, dst_r = src[mask], dst[mask]
             msg_src = H[src_r] @ self.W_r[r][s:e].t()    # (|E_r|, d_head)
             msg_dst = H[dst_r] @ self.W_r[r][s:e].t()
             concat  = torch.cat([msg_src, msg_dst], dim=1) # (|E_r|, 2*d_head)
             e_ij    = self.leaky_relu(concat @ self.a_r[h_idx, r])
             alpha   = _softmax_per_dst(e_ij, dst_r, N)
             agg     = torch.zeros(N, self.d_head, device=self._device)
             out_h  += agg.scatter_add(0, dst_r.unsqueeze(1).expand(-1, self.d_head),
                                       alpha.unsqueeze(1) * msg_src)
     out_heads.append(out_h)

 out = torch.cat(out_heads, dim=1)   # (N, d_out)

 a_r change de shape : (n_relations, 2*d_out) → (n_heads, n_relations, 2*d_head).
 Backward : aucun changement — torch.autograd.grad couvre automatiquement la nouvelle shape.

 Amélioration G — Refonte du verbalizer

 Reframe complet de l'objectif (CORRECTION défauts #3 et #4)

 Constat critique : les labels de nœuds dans les données verbalize sont des mots uniques ("économie", "souvent"). La surface gold est une phrase complète (50+ mots). Le BLEU entre "économie car environnement" et la phrase gold serait ≈ 0.03 même avec un connecteur parfait. La métrique BLEU contre la surface source est invalide.

 Redéfinition : le verbalizer produit une description structurée apprise du graphe causal, pas une reconstruction de la phrase source. Sa qualité se mesure par connector_precision@1 (bon connecteur sélectionné pour chaque arête).

 La phrase source est la responsabilité des frontends/LLMs. Le moteur produit un CausalIR ; le verbalizer produit une verbalisation structurelle lisible.

 Architecture :

 Pourquoi le fossé structurel persiste

 Les améliorations traitent les symptômes architecturaux. La cause racine reste l'absence de pré-entraînement :

 CGNP amélioré  = FastText 300-dim (wiki.fr.vec) + 2015 phrases annotées (1388 gold + 627 silver)
 CamemBERT       = 768-dim contextuels (138 Go texte fr) + 2015 phrases fine-tuning

 Même avec mean-pooling (A) et embeddings sujet/objet (B), le vecteur de nœud est 300-dim (wiki.fr.vec) contre 768-dim contextuel — facteur 2.6× de capacité. Les améliorations D (multi-tête) et E (empilement) ajoutent de la profondeur mais ne compensent pas la richesse d'entrée.

 Voie unique pour fermer le fossé dans la vision du moteur

 La seule voie technique compatible : plus de données annotées.

 2015 phrases → edge F1 ≈ à mesurer  (baseline actuelle sur mixte_final)
 2015 phrases → edge F1 ≈ baseline+0.06  (post améliorations A–G)
 5 000 phrases → edge F1 ≈ 0.65–0.70  (projection loi de scaling)
 20 000 phrases → edge F1 ≈ 0.75+  (compétitif sans pré-entraînement)

 Un transformer pré-entraîné atteint ~0.50 F1 à zéro données annotées (pré-entraînement seul), monte à ~0.82 avec 2015 exemples. CGNP commence à 0.00 et sa vraie baseline sur 2015 phrases est à mesurer. L'avantage transformer diminue à mesure que les données annotées augmentent.

 Les améliorations A–G permettent au moteur de remplir sa mission avec moins de données et d'atteindre son plafond architectural plus tôt. Elles ne changent pas la nature de la compétition avec les transformers : le moteur gagne sur le déploiement, l'explicabilité et l'ontologie contrôlée — pas sur le F1 brut.
