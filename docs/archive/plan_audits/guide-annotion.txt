Guide d'annotation — Dataset GCN-NL (pour Muse Spark)

 Objectif

 Annoter les phrases scrappées pour entraîner le moteur causal GCN.
 Source : gcn-tools/gcn-datasets/raw/sentences_20260921_183623.jsonl (18 948 phrases, FR/EN/ES/DE)
 Cible : enrichir gcn-datasets/real/train/train.json (536 → objectif 2 000+ phrases)

 ---

 Étape 0 — Filtrage : quelles phrases annoter ?

 N'annoter que les phrases causales. Une phrase est causale si elle exprime
 une relation de cause → effet, condition, ou séquence causale.

 Marqueurs à chercher (exemples, non exhaustifs) :

 ┌────────┬─────────────────────────────────────────────────────────────┐
 │ Langue │                          Marqueurs                          │
 ├────────┼─────────────────────────────────────────────────────────────┤
 │ FR     │ parce que, car, donc, puisque, si…alors, entraîne,          │
 │        │ provoque, permet, empêche, grâce à, à cause de              │
 ├────────┼─────────────────────────────────────────────────────────────┤
 │ EN     │ because, since, so, therefore, causes, leads to, enables,   │
 │        │ prevents, if…then, due to                                   │
 ├────────┼─────────────────────────────────────────────────────────────┤
 │ ES     │ porque, ya que, por lo tanto, causa, provoca, permite,      │
 │        │ impide, si…entonces                                         │
 ├────────┼─────────────────────────────────────────────────────────────┤
 │ DE     │ weil, da, deshalb, daher, führt zu, verursacht, ermöglicht, │
 │        │  verhindert, wenn…dann                                      │
 └────────┴─────────────────────────────────────────────────────────────┘

 Seuil minimal : 2 entités/événements distincts + 1 relation causale explicite.
 Exclure : phrases purement descriptives, listes, titres, phrases < 8 mots.

 ---

 Étape 1 — Structure de sortie (format gcn-nl JSON)

 Chaque phrase annotée doit produire un objet JSON de cette forme :

 {
   "id": "sNNN",
   "text": "La pluie a causé l'inondation.",
   "causal_pattern": "cause",
   "tokens": [ ... ],
   "cir": {
     "nodes": [ ... ],
     "edges": [ ... ]
   }
 }

 Toutes ces phrases sont regroupées dans :
 {
   "document": {
     "id": "doc-batch-001",
     "lang": "fr",
     "sentences": [ ... ]
   }
 }

 ---

 Étape 2 — Tokens (format UD simplifié)

 Pour chaque mot de la phrase, produire :

 {
   "id": 1,
   "form": "La",
   "lemma": "le",
   "pos": "DET",
   "dep_rel": "det",
   "dep_head": 3,
   "morph": {}
 }

 Valeurs pos (Universal POS tags) :
 NOUN, VERB, ADJ, ADV, DET, PRON, ADP, SCONJ, CCONJ, PUNCT, NUM, PROPN, AUX

 Valeurs dep_rel les plus fréquentes :
 root, nsubj, obj, advcl, mark, det, amod, advmod, punct, aux, case, nmod, obl

 dep_head = id du token gouverneur (0 si root)
 morph = dictionnaire vide {} si pas d'info morphologique

 ▎ ⚠ Spécifiquement pour les tokens causaux (marqueurs comme "parce que", "donc", "because") :
 ▎ ajouter optionnellement le champ gcn :
 ▎ "gcn": { "causal_type": "conjonction", "causal_class": "cause" }
 ▎ Ce champ est optionnel — les tokens sans gcn sont acceptés.

 ---

 Étape 3 — Nœuds CIR (cir.nodes)

 Un nœud = un événement, état, ou entité participant à la relation causale.

 Minimum : 2 nœuds par phrase.

 {
   "id": "n001",
   "type": "processus",
   "label": "chute(pluie)",
   "token_span": [3, 4],
   "origin": "explicit",
   "scope": "specific",
   "temporal_index": 0,
   "modifiers": [],
   "attributes": {
     "entity": "pluie",
     "quality": "chute"
   }
 }

 Types de nœuds (champ type) — 7 valeurs

 ┌─────────────────┬─────────────────────┬─────────────────────────────┐
 │      Type       │        Usage        │           Exemple           │
 ├─────────────────┼─────────────────────┼─────────────────────────────┤
 │ action          │ Action volontaire   │ "réduire les coûts",        │
 │                 │ d'un agent          │ "attaquer"                  │
 ├─────────────────┼─────────────────────┼─────────────────────────────┤
 │ processus       │ Changement ou       │ "baisser les ventes",       │
 │                 │ évolution           │ "augmenter la température"  │
 ├─────────────────┼─────────────────────┼─────────────────────────────┤
 │ etat            │ État stable d'une   │ "être vulnérable", "être    │
 │                 │ entité              │ actif"                      │
 ├─────────────────┼─────────────────────┼─────────────────────────────┤
 │ etat_systemique │ État d'un système   │ "inflation", "crise         │
 │                 │ complexe            │ économique"                 │
 ├─────────────────┼─────────────────────┼─────────────────────────────┤
 │ transition      │ Passage d'un état à │ "se connecter", "tomber en  │
 │                 │  un autre           │ panne"                      │
 ├─────────────────┼─────────────────────┼─────────────────────────────┤
 │ condition       │ Condition ou        │ "si le firewall est         │
 │                 │ prérequis           │ désactivé"                  │
 ├─────────────────┼─────────────────────┼─────────────────────────────┤
 │ entite          │ Objet ou acteur     │ "le serveur", "l'attaquant" │
 │                 │ (pas un événement)  │                             │
 └─────────────────┴─────────────────────┴─────────────────────────────┘

 Champ label

 Format conseillé : verbe(objet) ou nom(entité) ou description courte.
 Exemples : "baisser(ventes)", "réduire(coûts)", "inondation", "vulnérabilité CVE-2024-1234"

 Champ token_span

 [id_premier_token, id_dernier_token] — indices des tokens de la phrase qui correspondent au nœud.

 Champ temporal_index

 Ordre temporel des nœuds dans la phrase : 0 pour la cause, 1 pour l'effet, etc.

 Champ scope

 "specific" (événement ponctuel) ou "universal" (loi générale).

 Champ attributes (optionnel mais recommandé)

 {
   "entity": "nom de l'entité principale",
   "quality": "changement ou qualité",
   "agent": "qui agit",
   "patient": "qui subit"
 }

 ---

 Étape 4 — Arêtes CIR (cir.edges)

 Une arête = une relation causale entre deux nœuds.

 Minimum : 1 arête par phrase.

 {
   "source": "n001",
   "target": "n002",
   "relation": "cause",
   "attributes": {
     "confidence": 0.9,
     "explicit": true,
     "negated": false,
     "marker_token": 3
   }
 }

 Types de relations (champ relation) — 11 valeurs

 ┌────────────────────┬────────────────────┬───────────────────────────┐
 │      Relation      │       Usage        │          Exemple          │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ cause              │ A provoque         │ "la pluie cause           │
 │                    │ directement B      │ l'inondation"             │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ enable             │ A rend B possible  │ "le firewall désactivé    │
 │                    │                    │ permet l'accès"           │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ prevent            │ A empêche B        │ "le chiffrement prévient  │
 │                    │                    │ la fuite"                 │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ condition          │ Si A alors B       │ "si les ventes baissent,  │
 │                    │                    │ on réduit"                │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │                    │ A puis B           │ "d'abord l'infection,     │
 │ sequence           │ (temporel, pas     │ puis la propagation"      │
 │                    │ forcément causal)  │                           │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │                    │ B explique A       │ "on réduit les coûts car  │
 │ motivation         │ (causalité         │ les ventes baissent"      │
 │                    │ inversée)          │                           │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ concession         │ Même si A, quand   │ "malgré le patch, la      │
 │                    │ même B             │ vulnérabilité persiste"   │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ opposition         │ A s'oppose à B     │ "la défense s'oppose à    │
 │                    │                    │ l'attaque"                │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ filter             │ A filtre /         │ "le IDS filtre le trafic  │
 │                    │ sélectionne dans B │ malveillant"              │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ data_dependency    │ B dépend des       │ "l'alerte dépend des logs │
 │                    │ données de A       │  du firewall"             │
 ├────────────────────┼────────────────────┼───────────────────────────┤
 │ control_dependency │ B dépend du        │ "l'exécution dépend du    │
 │                    │ contrôle de A      │ token d'authentification" │
 └────────────────────┴────────────────────┴───────────────────────────┘

 Champ causal_pattern (niveau phrase)

 Mettre la relation principale de la phrase : "cause", "condition", "sequence", etc.

 Champ marker_token (optionnel)

 ID du token connecteur (ex: "parce que" → id du premier token du marqueur).

 Étape 6 — Règles de qualité

 1. Chaque phrase doit avoir ≥ 2 nœuds et ≥ 1 arête. Pas de phrase avec 0 edge.
 2. token_span doit pointer vers des tokens réels : [i, j] avec i ≤ j et les deux ids existent dans tokens.
 3. L'arête source et target doivent être des ids de nœuds valides définis dans nodes.
 4. Ne pas annoter les phrases ambiguës où la causalité n'est pas claire — les sauter.
 5. temporal_index : toujours 0 pour la cause/condition, 1+ pour l'effet.
 6. confidence : 1.0 si le marqueur est explicite ("parce que", "donc"), 0.8 si implicite.
