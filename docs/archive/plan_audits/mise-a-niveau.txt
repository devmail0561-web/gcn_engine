 Plan — Architecture discussion causale v2.0 (v5 — références vérifiées)

 Contexte et règles absolues

 Le moteur GCN produit des graphes causaux vérifiables. Ce plan couvre :
 (1) normalisation des données, (2) dataset N-aire, (3) interface discussion naturelle,
 (4) réponses argumentées.

 Règles absolues :
 - AUCUN YAML dans le moteur — YAML = gcn-tools/ uniquement. Pourquoi : le moteur apprend
   depuis les données, pas depuis des règles linguistiques hardcodées.
 - AUCUN --lang — PHASE12 l'a supprimé (v2.0 breaking). Pourquoi : réintroduire lang
   recrée une dépendance linguistique cachée et invalide l'isomorphisme fr↔en.
 - AUCUN hardcoding — pas de constantes magiques, règles, tables de mapping dans le moteur.
 - gcn-frontend-fr/en = bootstrap uniquement. Exception documentée : GCNBridgeParser
   appelle gcn analyze (Rust, FrenchParser) à l'inférence — compromis accepté (heuristique
   ~80-85%) faute de PyO3. Le binaire Rust est une dépendance de production assumée.

 Gate découplé :
 val_node_macro_f1 = 0.274 (cible 0.60) est un bloquant données, pas code.
 Toutes les phases infra/interface/qualité sont livrables sans atteindre ce gate.
 Seule la tête de prédiction de liens est gatée (gate = gcn-eval --gate --on-fail=warn,
 jamais fail-closed).

 Étape 0 — data/edge_norm.py : normaliseur unifié (prérequis à tout le reste)

 Pourquoi un module dédié : trois normaliseurs divergents existent dans le code actuel :
 - bootstrap.py:109-137 — défaut relation="cause", confidence=1.0 silencieux
 - bridge.py:111-150 — int() strict, warn agrégé, pas de défaut silencieux
 - instructions.py:84-94 — normalisation inexistante (drop silencieux des dicts)

 Un quatrième normaliseur créerait une incohérence systémique. Centraliser en
 gcn-python/src/gcn_python/data/edge_norm.py.

 Normalisation des ids — 3 conventions à unifier :
 - ir_emitter.py:39-50 : {"id": i} (entier Python)
 - ClauseRecord.node_id dans schema.py : string "n001" (zéro-paddé)
 - bootstrap.py : str(i) = "0", "1" (pas paddé)

 Règle : f"n{int(raw_id):03d}" pour les entiers (try/except ValueError si non-convertible).
 Si déjà string commençant par "n" suivi de chiffres → conserver. Si string purement numérique
 → f"n{int(s):03d}". Idempotent : "n001" → "n001".

 confidence absent → None, jamais 0.0 :
 query_report.py:250 fait f"{conf:.2f}" et :348 fait f"{conf:.0%}" — les deux
 crashent sur None. La règle : None signifie "annotation absente" ≠ "confiance nulle".
 Afficher "?" dans le rapport. Émettre warn agrégé.

 negated absent → None (pas False) :
 cgnp.py calcule is_negative via representation.py:37-38 (Polarity==Neg depuis root_morph).
 Ne jamais écraser cette détection en mettant negated=False par défaut depuis le normaliseur.
 None = "non renseigné", laissé à la détection du pipeline.

 Sanitization anti-injection :
 Labels et textes sources peuvent contenir \n, \r, séquences ANSI. Avant tout affichage
 dans query_report.py ou discuss.py : text.replace('\n', ' ').replace('\r', ' ').strip().

 Fichier cible : gcn-python/src/gcn_python/data/edge_norm.py (nouveau, ~100 lignes)

 Tests :
 - int(1) → "n001", int(0) → "n000" (idempotent)
 - str("n001") → "n001" (inchangé)
 - str("1") → "n001"
 - confidence=None → warn, pas de crash
 - relation absent → None + warn agrégé (pas de default silencieux)
 - negated absent → None (pas False)
 - \n dans label → sanitisé
 - tuple format [src,dst,attrs] et dict format {source,target,relation} tous deux acceptés

 Étape 1 — schema.py / json_reader.py / loader.py (migration v1→v2)

 1a. EdgeRecord.source: str → sources: list[str]

 Pourquoi la property ne suffit pas : @property source permet e.source en lecture,
 mais pas EdgeRecord(source="n001") (TypeError sur dataclass). dataclasses.asdict(),
 astuple(), replace() contournent les properties et ne voient que le champ sources.
 json_reader.py:143 fait e.source → TypeError après migration sans shim.

 Migration correcte :
 # schema.py — EdgeRecord
 @dataclass
 class EdgeRecord:
     sources: list[str]      # NOUVEAU — remplace source
     target: str
     relation: str
     confidence: float = 1.0
     explicit: bool = True
     negated: bool = False
     marker_token: Optional[int] = None

     def __post_init__(self):
         # Shim : accepte construction legacy EdgeRecord(source="n001")
         # mais sources est le champ canonique
         pass  # géré par __init__ override ou via from_legacy classmethod

 Alternative recommandée : @classmethod from_legacy(cls, source: str, ...) plutôt qu'un
 shim __post_init__ qui complique la sérialisation. Les appelants legacy passent par
 EdgeRecord.from_legacy(source=...).

 json_reader.py _parse_edge : lire "sources" en priorité, wraper "source" si absent.
 Si les deux présents → "sources" gagne (warn si conflit).

 loader.py TrainingSample : ajouter hyperedge_map avec default vide pour rétrocompat :

 Pourquoi default_factory : loader.py:139 et tout code appelant TrainingSample(...)

 Script gcn-datasets/scripts/migrate_v1_v2.py :
 - Ajoute "schema_version": "2.0" à chaque document
 - Wrape "source": "n001" → "sources": ["n001"] dans toutes les arêtes

 1b. hyperedge_map dans _to_sample

 Bypass gap>1 pour les N-arêtes :
 Pourquoi : le filtre gap>1 est conçu pour les arêtes binaires longue-distance. Une
 hyperarête [n001, n003] → n005 est non-consécutive par nature — pas une arête longue-distance
 ordinaire. Si len(e.sources) > 1 → router vers hyperedge_map sans vérifier gap.

 Remapping valid_clause_idxs (critique) :
 loader.py filtre les spans vides AVANT _to_sample. Les indices dans node_id_to_idx
 après filtrage ne correspondent plus aux indices originaux. Vérifier l'alignement avec
 train.py (lignes autour de valid_clause_idxs) et cgnp.py:347-361 (filter_edge_cache).

 frozenset(str) et order temporel :
 frozenset perd l'ordre. Pour sequence N-aire (A puis B → C), l'ordre est sémantiquement
 significatif. Limitation documentée en ADR : sequence N-aire est non-ordonné en v2.0.
 Clé : (frozenset(sources_as_str), target_idx) — la relation est dans la valeur.

 Relations inverses bidi :
 RELATION_TYPES_INV = [r + "_inv" for r in RELATION_TYPES] (constants.py).
 Arêtes backward binaires : rel_idx + len(RELATION_TYPES) si --bidirectional.
 Ne pas construire "_inv_cause" à la main.

 Status quo à documenter (ADR) :
 Actuellement cohérent par vacuité : json_reader.py:93,101 → morph={},

 Étape 3 — graph_vecs.npz : vecteurs séparés avec clé stable

 Clé stable :
 SHA-256 de sentence_text.encode("utf-8") entier (pas [:80] — trop de collisions) +
 "_" + str(node_position_in_valid_clause_idxs).
 Pourquoi valid_clause_idxs et pas position dans cir["nodes"] :
 get_enriched_vectors() (engine.py:363-371) retourne _cached_enriched_vecs depuis le
 chemin analyze(). Dans ce chemin (bridge), il n'y a pas de filtrage des spans vides — N
 vectors = N nodes. Dans le chemin train (reps_from_sentence), il y a filtrage. Utiliser
 la position dans cir["nodes"] directement pour le chemin analyze().

 Manifest JSON :
 {
   "checkpoint_hash": "sha256:<hash_poids_triés>",
   "d_eff": 196,
   "created_at": "ISO8601",
   "entries": {
     "<sha256_text>_<node_pos>": {"node_id": "n001", "node_label": "...", "shape": [196]}
   }
 }

 Hash canonique du checkpoint :
 sha256(concat([weights[k].tobytes() for k in sorted(arch_keys)])) — stable même si le
 format ZIP varie. Pas de MD5 sur le fichier NPZ (instable).

 NpzFile LRU : ouvrir avec np.load(path, allow_pickle=False, mmap_mode='r') et tenir
 le handle ouvert (LRU cache). Éviter de rouvrir le ZIP à chaque accès clé.

 Fallback _minimal_reps_from_labels : qualité dégradée documentée (root_morph={},
 has_advcl=False, is_negative=False, root_pos=VERB fixe dans train.py:26-39).
 Utiliser seulement si manifest absent ou checkpoint changé.
